# 架构

一日一记的极简日记：日期明文可查，正文逐字段加密，数据放在本机的一个 SQLite 文件里。

## 模块图与依赖方向

```text
main.rs              装配：找数据目录 → 开库 → 起窗口，不写 SQL 也不写布局
  └── app.rs         控制器：策略、落盘时机、错误处理、锁定流程
        ├── ui/      视图：只画界面，只表达意图
        │      └── model.rs       （视图需要认识的数据形状：MonthSheet / Change）
        └── store/   存储：Vault 接口 + SQLite 实现
               ├── model.rs
               └── crypto.rs     密钥派生与字段加密
      model.rs       领域数据与不变量（月份边界、空白等于没写）
      crypto.rs      主密码 → 密钥 → 单字段密文
      paths.rs       数据目录与数据库路径
      window_state.rs 窗口尺寸与最大化标志（一行文本，没有正文）
```

依赖只能沿着箭头走，另外两条硬约束：

- `ui/` 里不出现 `rusqlite`、不出现 `eframe`（只有 `egui` 与纯数据）；
- `store/` 里不出现任何 `egui` 类型；
- `main.rs` 不认识 SQL，也不认识界面细节，只做装配与错误汇报。

`ui/` 认识 `model` 是因为它要渲染这些数据形状，而不是要操作它们：
`MonthSheet` 没有 IO，`Change` 没有副作用，都属于"可以跨层传的纯数据"。

## 数据流

读：

```text
日历翻月 / 点某一天
  → app.switch_month(MonthKey)      旧页先 flush，再换页
  → Vault::load_month(key)          WHERE date >= '本月1号' AND date < '下月1号'
  → store 用会话密钥逐行 open(aad = 日期字符串)
  → MonthSheet（只含非空正文）→ 日记面板 / 日历打点
```

写：

```text
在某一行的输入框里打字
  → Diary 发现 response.changed() → Change::set(date, text)（纯空白自动变 Delete）
  → app 先落到 MonthSheet 缓存（界面这一帧就看到结果）
  → app 把 Change 交给 SaveScheduler（同一天只留最后一次）
  → 安静 0.4 秒后 → Vault::apply(&[Change]) 一个事务写完
```

`apply` 内部：一次事务 + 两条 prepared statement（upsert / delete），中间任何一条失败整批回滚。

## 落盘时机

| 时机 | 行为 |
| --- | --- |
| 打字 | 防抖 0.4 秒，一次写一批 |
| 离开一行（失焦） | 立刻写 |
| 删除、撤销 | 立刻写 |
| 切日期、切月份 | 立刻写（换页前必须落盘，否则缓存里的编辑会被挤掉） |
| 点锁定 | 立刻写，写完才丢密钥；写失败就拒绝锁定并报错 |
| 关窗 | 先记下窗口尺寸（与正文无关，有没有待写的编辑都要记）→ 拦截 `close_requested` → 写完 → 自己再请求关闭；写失败就不关窗 |
| 错误条上的"重试" | 立刻写一次；成功则错误条消失、状态字回到"已保存"，失败则保持原样，不重排帧。编辑还压在队里时错误条上只有这一枚按钮，没有"知道了"——收起来等于把重试入口一起收走 |
| 写盘失败 | 编辑留在队列里，不自动重试、不排帧（避免磁盘坏了忙转），等"重试"、下一次编辑或换日期／翻月份 |

顶栏的保存状态字由队列状态直接算出（`ui::shell::SaveState`）：队列空是"已保存"、攒着等防抖是"保存中"、
上次写失败是"未保存"。三个状态都不额外排帧——它们翻转的那一帧本来就是一次重绘。

## 表结构

```sql
PRAGMA journal_mode = WAL;      -- 读写不互相堵
PRAGMA synchronous = NORMAL;    -- 断电最多丢最后一个事务
PRAGMA busy_timeout = 5000;     -- 撞锁时等一会儿，不要立刻失败
PRAGMA foreign_keys = ON;       -- 现在用不上，为以后加表留着

CREATE TABLE meta (
    key   TEXT PRIMARY KEY,
    value BLOB NOT NULL
);
-- 已占用的 key：
--   kdf.params    参数串 "argon2id$m=19456,t=2,p=1$<hex salt>"
--   kdf.verifier  验证块（用派生密钥封住一句固定明文，空库也能验密码对不对）

CREATE TABLE entries (
    date       TEXT PRIMARY KEY,  -- 'YYYY-MM-DD'，明文：日历打点与按月查询要用
    body       BLOB NOT NULL,     -- nonce(12) || 密文 || tag(16)
    updated_at INTEGER NOT NULL,  -- Unix 秒
    format     INTEGER NOT NULL   -- 这一行的密文格式版本
);
```

迁移用 SQLite 自带的 `PRAGMA user_version` 加一张顺序迁移函数表（`store/sqlite.rs` 的 `MIGRATIONS`）：
一个迁移一个事务，中途失败整个库还停在上一个干净的版本。
库的版本比程序新时直接拒绝打开——按老结构乱写比打不开危险得多。

SQLite 用 `rusqlite` 的 `bundled` 特性编译进去，不依赖系统里装没装 SQLite。

## 加密参数与泄露面

| 项 | 取值 |
| --- | --- |
| 密钥派生 | Argon2id，m = 19456 KiB (19 MiB)、t = 2、p = 1（OWASP 最低推荐档），16 字节随机盐 |
| 参数存放 | `meta.kdf.params`，每个库带着自己那一套，调参不用改代码 |
| 字段加密 | ChaCha20-Poly1305，每条密文新随机 12 字节 nonce |
| AAD | 日期字符串 `YYYY-MM-DD`，密文被挪到别的日期就解不开 |
| 密钥生命周期 | 只在 `crypto::Session` 里，`lock()` 一次 drop 即清零；密码缓冲用 `Zeroizing` |

**加密的**：`entries.body`（正文一个字都不落明文）。
**不加密的**：日期、`updated_at`、行的增删。

也就是说，拿到 `today.db` 的人能看出"哪几天写过、什么时候最后改的、一共多少天"，
但看不到任何一个字的内容。这是"SQLite + 加密字段"的字面含义，
也是日记这个场景下可接受的代价——真正的秘密是内容，不是"今天写过东西"这件事本身。

## 视觉系统（点色的用法）

整套界面只有一整套暖色（骨白 → 墨黑），状态靠**墨色深浅 + 一根细线**表达：
要强调"当前"就填一块实墨，要说明其余情况就改字色和字号。
点色只用于"必须立刻被看见"的事。具体到 token：

| 角色 | token | 用在哪 |
| --- | --- | --- |
| 骨架 | `CANVAS` `SURFACE` `SIDEBAR` `HOVER` `PRESSED` `HAIRLINE` | 底、面板、悬停、结构线 |
| 文字 | `INK_DEEP` `INK` `MUTED` `FAINT` | 四档墨色，从"当前"到"最弱" |
| 点色 | `RED_BG/FG` | 错误提示条；周末的日期数字用它的深色版（日历惯例） |
| 点色 | `YELLOW_BG/FG` | 撤销提示条（瞬态、可操作） |
| 选中 | `SELECTION_BG` | 选中文字的高亮，暖沙色，与纸同族 |

"当前/选中"这个状态一律用**实心墨块**说：日历上选中的那天、解锁卡片的主按钮。
次要状态（"今天"、"N 字"、"空白"）**连框都不要**，
用 `theme::Piece::state` 画一枚小号等宽状态字：深浅定轻重，字号与字距把它和正文、日期戳分开。
一段文字里中英混排时，`theme::mixed` 把两种脚本各自成段、压在同一条基线上（见下面"按基线摆"那条）。
全应用没有胶囊形状。

想加点色之前先问一句：这是不是"出错"或者"刚刚被你改掉"？不是就用墨色深浅。

四档墨色的对比度是量过的：`INK_DEEP` / `INK` 在三层底色上都在 11:1 以上，
`MUTED` 卡在 4.8:1 以上（AA 线是 4.5）；`FAINT` 只有 1.9:1，
所以它只能出现在装饰性的位置上（品牌副标、周数、星期缩写），
一旦某个字得让人看清，就不该用 `FAINT`。圆角也是同一套尺子：
6（控件与格子）/ 8（行高亮）/ 10（提示条）/ 12（卡片），没有第五种。

## 决策记录

### 为什么状态不用颜色，颜色只留两种

早先的状态标签是彩色胶囊：今天用柔和绿、字数用柔和蓝。
但它们都是**装饰性**的——"今天"已经在日历上有墨块、在行内提示里写了两个地方，
字数也不需要颜色来强调。在一个自称暖调单色的系统里，
两块冷色胶囊是最先被眼睛挑出来的异物。
后来连胶囊这个形状也去掉了：状态缩成一枚小号等宽字，与日期戳同一种语言。

现在的规则：点色等于"必须立刻被看见"，也就是出错（红）和撤销（黄）两种；
其余状态用实心墨块和墨色四档深浅表达。
同一个道理下，选中文字的高亮也从冷蓝换成了暖沙（`SELECTION_BG`）：
在这个日记里，那是纸上的荧光笔，不是网页的选中蓝。

### 为什么一行小件按基线摆，而不是交给横向布局

`ui.horizontal` 按**外框**居中摆小件，而两套字体的外框比例并不一样：
Consolas 的行框 1.17em（升部 0.74em），雅黑 1.32em（升部 1.06em）。
后果是两处系统性错位：

- 两段不同字号/字体的文字并排（`ToDay` 与 `一日一记`、`Enter` 与 `下一行`、`3 / 30` 与 `本月记录`）：
  外框居中等价于把两条基线摆在不同的高度，差 2~3pt；
- 同一段里中英混排时，`egui` 给每个字形定基线的公式是
  "两套外框居中对齐"，于是中文比数字低 0.24em：日期戳里的"周四"、
  状态字里的"N 字"都这样。

所以 `theme` 里有一组按基线摆的类型：`Piece`（一行里的一段：文字 / 键帽 / 按钮 / 分隔线）、
`line()`（摆一行：先量外框，再对齐基线）、`mixed_pieces()`（中英各自成段）。
状态字、键帽、幽灵按钮都从这组类型上长出来，全应用只有一条对齐规则。
这是分布式的代价：同一个 family 里混排、或跨 family 混排，都得先把脚本切开。

### 为什么装订线在输入框排好之后才回填

日号与一天的第一行正文必须压在同一条基线上：这条线是正文块第一行的外框顶边再加一个字体升部。
（正文块上下各有 `ROW_PAD_Y` 的内边距，算基线时要先把它让开；升部拿一个汉字量出来，
中文的字身最满，行框由它定。）
所以一行的顺序是：装订线先占位 → 排输入框 → 回头把日号与星期画到那条线上。
星期在日号右边，两者右对齐——都是定宽，于是日号与星期各成一列。
一天写长了行会自己长高，装订线不动：它压的是块的第一行，不跟着块往下走。

三个测试盯着这几条不变量：`every_piece_shares_one_baseline`（一行里每段都压在同一条基线上）、
`the_gutter_sits_on_the_body_baseline`（装订线落在底块内、落在递给它的基线上）、
`a_row_keeps_its_gutter_on_the_text_baseline`（真跑一帧：日号与正文的基线相等，
`+ ROW_PAD_Y` 这个偏移也算在内）。

### 为什么一天是一条会长高的正文块

一天一条记录，记录里可以有多行：正文用 `TextEdit::multiline`，在列宽里自动换行、随内容长高，
不折叠、不在行内滚动（取舍见"已知取舍"）。两个细节决定了它长什么样：

- `desired_rows(1)`：multiline 默认按 4 行给高度，空行与单行会白白长成 4 行高；
- 正文块上下各 8px 的透气走 `Frame::inner_margin`（给了 `Frame` 之后 `margin` 不作数），
  于是单行与空行在 40px 的最小行高里居中：一行正文约 20.5px + 上下各 8px 仍然装得下，
  正文纵向位置与改前一致（`an_empty_or_single_line_row_stays_one_line_tall` 盯着这个）。

键位分工由一个细节定下来：multiline 的 `return_key` 默认只认**无修饰键**的 `Enter`，
`Ctrl`/`Cmd`+`Enter` 既不会插换行、也不会被输入框吃掉，所以它能安全地当"下一天"。

### 为什么只加密 body，不做整库加密（SQLCipher）

整库加密要换 SQLite 实现（多一个 C 依赖或自己维护构建），
而本项目要的能力只有两条：按月查一批天、正文不可读。
字段级加密用现成 crate 就能做到，代价是元数据泄露（见上）。

### 为什么日期保持明文

日历上的小圆点需要知道"哪几天有记录"，按月翻页需要一次范围查询。
日期进密文就只能整库解密再过滤，随着年份增长越来越慢。
日期本身不敏感（"2025-09-17 写过一行"），所以用明文换可查询性。

### 为什么参数串里带盐，而不是单独一个 `kdf.salt` 键

参数和盐必须配套。放两个键就存在"只改了一个"的中间状态，
而且这种错配要到解密失败时才被发现。合成一个串就是一条记录，没有半套配置的可能。

### 为什么不给 `entries(date)` 再建一个索引

`date TEXT PRIMARY KEY` 已经带了唯一索引，`WHERE date >= ? AND date < ?` 走的是它。
再加一条同名索引只让写入更慢。

### 为什么 `Vault` 是 trait

控制器不该知道底下是 SQLite。接口只有六个方法（`needs_setup` / `setup` / `unlock` / `lock` /
`load_month` / `apply`），换成文件、换成远端存储都不用动 ui 与 app。
同时它也是一道安全边界：密钥在实现内部，`app` 拿不到，所以"绕过加密写盘"写不出来。

### 为什么视图不持有领域数据

正文的唯一副本是控制器的 `MonthSheet`（以及库里的密文）。
`Diary` 只留视图状态（滚到哪儿、光标在哪一行、刚删掉什么用于撤销）。
锁定之后内存里也不该剩正文，所以要扔掉的不只缓存：`App::lock` 把缓存换成一页空的，
同时清掉 `Diary` 的撤销暂存（`undo_toast` 过期时也清）与 `egui` 替每个 `TextEdit`
存下的 `TextEditState`——它的撤销缓冲里有一份正文（见 `ui::diary::forget_text_edits`）。

### 为什么 Argon2 派生是同步的

单次 19 MiB、t=2 的派生在本机约 50–100 ms，出现在启动或解锁这一下，用户感知不到卡顿。
真遇到慢机器（>200 ms 可感），把派生挪到后台线程即可，`Vault` 接口不变。

### 为什么写失败之后不排帧，而要用户点"重试"

写失败后 `SaveScheduler` 把编辑放回队列并置 `stuck`，这时 `is_due` 恒为假。
早先排帧只看"队列非空"，而到点时间已经归零，于是变成了每 10 ms 一帧的空转：
界面什么都不变，CPU 一直转。现在排帧的判据是 `needs_wakeup()`（队列非空 **且** 没卡住），
卡住时一帧都不排，也就没有"排了帧也没人写"这个循环。
重新开始的入口都是显式动作：点错误条上的"重试"、下一次编辑、换日期或翻月份、关窗或锁定时的落盘。
绘制路径本身一次都不试——日历只在用户真的翻页那一帧才换页（见 `App::switch_month` 的注释），
所以写失败之后每一帧重绘都不会再碰一次磁盘。

错误条上的话也分两种（`app::Fault`）：写盘失败跟着队列走，写成功就收掉；读盘失败与密码不对
与队列无关，留到用户点"知道了"——一次成功的写入治不了读失败，那一页其实还是空的兜底页。

### 为什么关掉 4× MSAA、把适配器偏好降到低功耗

`epaint` 自己按 1 px feathering 抗锯齿，圆角、结构线、光晕都不依赖 MSAA；
4× MSAA 只会让 wgpu 多建一个 4 倍大的采样目标、每帧多做一次 resolve，而这是个 2D 界面。
适配器偏好从 `HighPerformance` 改成 `LowPower`：日记本不该为它叫醒独显。
两条都留给 wgpu 自己的环境变量做逃生口（`WGPU_POWER_PREF=high`、`WGPU_BACKEND=…`），没有另造配置项。

### 为什么只记窗口尺寸，不记位置

记下的坐标在换显示器或拔掉外接屏之后可能落在看不见的地方，而尺寸与最大化不会因此失效。
`window_state::remember` 收 `Option`：最大化或全屏关窗时量到的 `inner_rect` 是整屏尺寸，
不能当作"普通尺寸"记下来，所以这时传 `None`——保留上一次的普通尺寸，
下次从最大化还原才不会得到一个和屏幕一样大的窗口。
全屏也要认：`ViewportInfo::maximized` 不是每帧都刷新（`egui_winit` 在 macOS 上只在窗口创建
那一次采样它），而 macOS 那个绿色按钮给的正是全屏；`fullscreen` 每帧都更新，所以两个一起看。

### 为什么中文字体只读一次

字体候选是一串路径，每个角色取第一个存在的文件。`sans-cjk` 与 `mono-cjk` 本来指向同一个文件
（Windows 上是 `msyh.ttc`，≈19 MB），早先各读一遍、各存一份 `Vec<u8>`。
同一个文件在两个角色里渲染结果逐像素相同，所以 `load_role` 现在带一张"路径 → 键名"的表：
第二个角色直接复用那个键，不再读、不再往 `font_data` 里插第二份。
读到的字体以 `Arc<FontData>` 存放，两个 family 的候选列表指向同一个 `Arc`。

### 为什么依赖在 dev profile 里也开优化

日常用 `cargo run`，跑的是 debug 构建，而字形光栅化（`epaint` 的 `vello_cpu`）、排版（`harfrust`）
与 `wgpu` 都在依赖里：未优化时它们慢一个数量级，"解锁后卡一下、打字发涩"主要来自这里。
`Cargo.toml` 于是给 `[profile.dev.package."*"]` 开 `opt-level = 3`，自己的 crate 只开 1——
改代码之后的重编还是秒级。代价是改完这一段第一次 `cargo test` / `cargo clippy`
要重编全部依赖（`wgpu` / `naga` 在优化下要几分钟），之后走缓存。
`panic = "abort"` 不加：那会改掉 panic 的语义。

### 为什么启动时不自己发 `Visible(true)`

`eframe` 0.36 的 wgpu 集成已经把根窗口藏着建（`create_window` 结尾的 `.with_visible(false)`），
第一帧画完（`post_rendering`）再 `set_visible(true)`，为的就是不闪白底。
控制器再自己发一次既是重复的，又比"画完再显形"早，所以这件事留给 eframe，
`main` 只负责尺寸、最小尺寸与最大化。

## 已知取舍

- 关窗时先刷盘再关。进程被强杀（任务管理器）时最多丢最后约 0.4 秒的输入。
- 落盘在 UI 线程上做。`busy_timeout = 5000` 意味着撞锁时最坏会冻界面 5 秒；
  搬到后台线程要改 `Vault` / `App` 的时序契约，另开一轮。
- 顶栏的保存状态字只在三个词之间翻转，不做动画、不做进度条：
  它要回答的是"现在写没写进去"，不是"写了多少"。
- 窗口只记尺寸与是否最大化，不记位置（理由见决策记录）。
- 日历翻到别的月份时，抬头那枚"N 字"标签会显示"空白"：缓存只留当前这一页，
  选中的那天不在这一页里。日期与星期照常显示。
- 解锁界面的密码框是自己画的框（全局样式把输入框底色做成了透明，
  靠它画不出"这里能输入"的暗示）。
- 一天写很长时这一行就很长：不折叠、不在行内滚动，整块跟着外层滚动条走（文档式行为）。
